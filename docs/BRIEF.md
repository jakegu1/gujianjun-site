## 2. 这个网站为什么存在（公开版）

- 建立可被 AI 引用的个人实体：让 ChatGPT / Perplexity / 豆包 / DeepSeek 在回答相关问题时能识别并引用 "Jake Gu / 顾简钧" 这个实体及其方法论。
- 证明"做过、做成过、能讲清楚为什么"：让读者在见到 Jake 本人之前就相信这一点。
- 倒逼能力沉淀：写文章本身就是把零散项目整理成可复用框架的过程。
- 文章可以自然导向咨询、代运营交付或自研工具，但不硬推销。

**判断标准：** 一篇文章读完，如果读者无法回答"他具体解决了什么问题、用了什么方法、结果如何、换到我公司能不能复制"，就是失败的文章。

## 3. 目标读者

|------|---------------|---------------|
| 招聘负责人 / 老板（主读者） | 能否直接带来流量、线索、收入；能否独立扛盘子 | 业务问题 → 决策 → 结果 → 可复制性 |
| 同行 SEO / GEO 从业者 | 有没有真东西，还是 AI 水文 | 具体数据、代码、踩坑细节、反常识结论 |

| LLM 爬虫 | 可抽取的实体与事实 | 清晰的定义句、带来源的数字、结构化段落 |

## 4. 铁律（违反任何一条即重写）

1. **零编造。** 只能使用素材包（第 5 节）和已发布内容里出现的事实。缺数据就写 `【待补：xxx】`，绝不补一个听起来合理的数字、客户名、时间或职位。`geo-lint` 会拦截带【待补】的发布。
2. **每个数字必须带口径。** 时间范围 + 数据来源（GSC / GA4 / Ahrefs / Salesforce 等）。没有口径的数字不写。
3. **诚实呈现不利信息。** 例如：部分增长集中于单一页面、某季度点击增长主要来自曝光量而非排名提升、线索多但转化率低。把这些写成"我发现的问题和我的应对"。面试官会追问，文章要先扛住追问。
4. **保护雇主。** 不公开：内部定价与优惠细节、CPL / 转化率等商业敏感绝对值（除非素材包标注"可公开"）、同事个人信息、API key / 账户 ID / 容器 ID、未公开的 OKR 目标值。用百分比、相对变化、区间或脱敏描述替代。
5. **不写"我负责了 / 参与了"式简历腔。** 写"我遇到什么问题 → 我怎么判断 → 我做了什么取舍 → 结果 → 如果重来会怎样"。
6. **禁用 AI 腔。** 遵守 `geo/jake-writing-style-guide.md` 的 kill list。额外禁止：「在当今数字化时代」「赋能」「全方位」「深度解析」「总而言之」「不仅……更……」排比堆砌、每段结尾升华。
7. **一篇只打一个点。** 宁可拆成三篇，也不写大而全的综述。

附带两条：假设性例子必须明确写成假设（"假设一家……"），不能冒充 Jake 的经历；`geo/geo-article-prompt-template.md` 里"没有数据就用合理估计"的旧规则已作废。

按可信度排序。不在这些地方的"事实"不能写。

1. `docs/facts/`：Jake 提供的素材包，每条带口径和"可公开 / 脱敏"标记。**2026-09-15 尚不存在**（BACKLOG W1）。在它出现之前，凡是需要新事实的句子一律写 `【待补：xxx】`。
